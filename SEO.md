# Nexlink SEO Guide

This document explains how Nexlink's search-engine setup works, how to verify
it locally, how to deploy it, and how to get it indexed by Google.

## 1. Key URLs

| What | URL |
| ---- | --- |
| Homepage (production) | https://nexlink-app.onrender.com/ |
| robots.txt | https://nexlink-app.onrender.com/robots.txt |
| sitemap.xml | https://nexlink-app.onrender.com/sitemap.xml |
| favicon | https://nexlink-app.onrender.com/favicon.ico |
| Web manifest | https://nexlink-app.onrender.com/static/manifest.json |
| Social image (og:image / twitter:image) | https://nexlink-app.onrender.com/static/images/icon-512.png |

## 2. Homepage metadata

The public landing page (`/`) is the only indexable page on the site.

* **Title:** `Nexlink — Modern Messaging & Chat App`
* **H1:** `Nexlink — connect and chat online`
* **Meta description:** `Nexlink is a modern messaging and chat web app for private, real-time conversations — create a free account and connect with your people online.`
* **Canonical:** `https://nexlink-app.onrender.com/` (from `SITE_URL`)
* **Open Graph + Twitter card:** title, description, url, site name "Nexlink", image `icon-512.png`
* **JSON-LD:** `WebApplication` schema (`CommunicationApplication`, `operatingSystem: Web`, feature list of real features only, `offers.price: 0`). No fake ratings, reviews, or user counts.

All of this is centralized in `config/seo.py` and rendered by
`templates/partials/seo_head.html`. Brand strings live in one place — do not
duplicate them in templates.

## 3. robots.txt

Served by Django (view in `config/urls.py`, template `templates/robots.txt`):

* Allows crawling of the homepage and static assets
* Disallows `/api/`, `/admin/`, `/accounts/profile/`, `/accounts/settings/`, `/chat/`
* Points at the sitemap using the environment-aware `SITE_URL`

Edit `templates/robots.txt` to change it — never hard-code a URL there.

## 4. sitemap.xml

Generated by Django's sitemap framework (`django.contrib.sitemaps`, class in
`config/sitemaps.py`). It contains **only** the public homepage. Add an entry
to `StaticViewSitemap.items()` if a genuinely public page is ever added
(about/help/contact/etc.) — never add login, dashboard, chat, profile, API or
POST-only URLs.

## 5. Public (indexable) vs private (noindex) pages

| Page | Indexable? | Mechanism |
| ---- | ---------- | --------- |
| `/` for anonymous visitors | ✅ Yes | Landing page with full SEO metadata |
| `/` for signed-in users | ❌ No | Redirects to dashboard, which is noindex |
| `/chats/`, `/chat/<id>/` (dashboard, requires login) | ❌ No | `@login_required` + `<meta name="robots" content="noindex, nofollow">` |
| `/accounts/login/`, `/accounts/register/`, password pages | ❌ No | `noindex, nofollow` via `seo_head` block |
| `/accounts/profile/`, `/accounts/settings/` | ❌ No | `noindex` + blocked in robots.txt |
| `/api/**` (all JSON endpoints) | ❌ No | Blocked in robots.txt; never linked publicly |
| `/media/**` (user uploads) | ❌ No | Blocked in robots.txt |

The dashboard additionally never renders private data into public pages: the
landing page is a static template with no user data.

## 6. Environment variables

| Variable | Purpose | Example |
| -------- | ------- | ------- |
| `SITE_URL` | Base URL for canonical, OG, sitemap, JSON-LD | `https://nexlink-app.onrender.com` |
| `GOOGLE_SITE_VERIFICATION` | Google Search Console meta-tag verification | value from GSC (no quotes, no `content=`) |

`SITE_URL` is defined in `config/settings.py`. On Render set it to
`https://nexlink-app.onrender.com` (no trailing slash). If unset, settings fall
back to the first https `CSRF_TRUSTED_ORIGIN`, then `http://127.0.0.1:8000` for
local development — so dev never leaks into prod and vice versa.

## 7. Google Search Console setup

1. Go to https://search.google.com/search-console → **Add property** → URL prefix → `https://nexlink-app.onrender.com/`
2. Choose the **HTML tag** verification method. Google gives you a value like
   `google-site-verification=AbC123...` — copy **only the token part after `=`**.
3. On the Render dashboard → nexlink-app service → **Environment** → add:
   * Key: `GOOGLE_SITE_VERIFICATION`
   * Value: `AbC123...` (the token only)
4. Save — Render redeploys automatically on env change.
5. Back in Search Console click **Verify**. The `<meta name="google-site-verification">`
   tag is emitted on every page that includes `seo_head` (homepage + auth pages).
6. Once verified: **Sitemaps** → enter `sitemap.xml` → Submit.
7. For faster first indexing use **URL Inspection** → enter `https://nexlink-app.onrender.com/` → **Request indexing**.

## 8. Testing SEO locally

```bash
# Full test suite (includes the SEOViewTests class)
python manage.py test

# System checks
python manage.py check

# 16-point SEO audit (homepage, robots, sitemap, icons, noindex rules)
python manage.py check_seo

# Against a running server instead of the test client:
python manage.py check_seo http://127.0.0.1:8000
```

After deploying, spot-check production:

```bash
curl -s https://nexlink-app.onrender.com/robots.txt
curl -s https://nexlink-app.onrender.com/sitemap.xml
curl -s https://nexlink-app.onrender.com/ | grep -E 'canonical|og:title|ld\+json'
```

## 9. Deploying to Render

1. Commit and push to `main` (`autoDeploy: true` in render.yaml).
2. Watch the deploy in the Render dashboard (or the API). Build takes ~2 min.
3. Smoke-test: homepage 200 with canonical `https://nexlink-app.onrender.com/`,
   robots.txt 200, sitemap 200, `/chats/` → 302 to login, login still works.

No Render settings need to change beyond the optional env vars above — the
existing service, database, Redis and static-file configuration are untouched.

## 10. What NOT to change

* **`config/seo.py`** — single source of truth for brand, title, description,
  canonical and JSON-LD. Editing templates directly creates drift.
* **`@login_required` on `dashboard()`** in `messaging/page_views.py` — this is
  the guard that keeps the chat dashboard (`/chats/`) out of reach for both
  crawlers and anonymous users. Removing it fails the test suite.
* **`seo_noindex=True` on auth templates** and the dashboard — private pages
  must stay out of the index.
* **`templates/robots.txt` / `config/sitemaps.py`** — keep private URLs out of
  both.
* **The landing template's H1** — exactly one H1 per page; heading structure is
  asserted by tests (`check_seo`, `SEOViewTests`).
* **Manifest, favicon, service worker** — existing PWA branding already matches
  the Nexlink brand; the og:image points at the real `icon-512.png`.

## 11. Notes on the "Naklink" misspelling

The landing page includes one natural sentence acknowledging that people may
search for "Naklink". It is framed as a misspelling of Nexlink, not as a
separate product, and no doorway pages or misleading content were created.
